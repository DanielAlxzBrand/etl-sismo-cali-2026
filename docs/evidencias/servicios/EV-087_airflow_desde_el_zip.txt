# Airflow construido y ejecutado desde el zip en una carpeta de otro nombre
- comando: `preparar_airflow.py y docker compose -p servicios_prueba (build, up, dags list, dags trigger, down) sobre un zip descomprimido en una carpeta temporal`
- fecha: 2026-11-15T00:21:40-05:00 (America/Bogota)
- código de salida: 0

- Python: 3.13.0
- commit del repositorio: b109dd1

Cómo lo haría una persona que recibe el zip, en carpetas temporales y con un proyecto de Docker propio (`servicios_prueba`) y el puerto 8082 (el 8080 y el 8081 no se tocaron). Se hizo con un script de la sesión de trabajo que sigue, uno por uno, estos pasos:
1. clon del commit de trabajo en una carpeta temporal y zip con `make_dist.empaquetar` dentro de ese clon (nunca en `dist/`): 492 archivos y 19,9 MB; trae `orquestacion/docker-compose.yaml`, `servicios/phpmyadmin/docker-compose.yaml` y `scripts/orquestacion/preparar_airflow.py`: sí; sin ningún `.env`: sí.
2. descompresión en una carpeta de nombre distinto de `etl_sismo_cali_2026` y con espacios (`proyecto sismo de prueba`) y copia de un `.env` de prueba tomado del real **solo dentro de esa carpeta temporal** (se borró al final).
3. `preparar_airflow.py` con un destino temporal hermano y `--puerto 8082`.
4. `docker compose -p servicios_prueba build`, `up airflow-init`, `up -d`, comprobación de la interfaz, `dags list`, `dags list-import-errors`, `dags unpause`, `dags trigger`, espera de las cuatro tareas, comprobación de `data/` y de MySQL.
5. `docker compose -p servicios_prueba down -v --rmi local --remove-orphans`: contenedores, red, volúmenes e imágenes construidas desaparecieron; `docker ps -a`, los volúmenes, las redes y las imágenes quedaron como antes (la única diferencia con el inicio fue la imagen de phpMyAdmin que se descargó para otra prueba).
